# @wmaurer/effect-ai-amazon-bedrock

## Unreleased

Amazon Bedrock guardrails are supported. Every finish part now carries `metadata.amazonBedrock`, also without a guardrail.

- Add `guardrailConfig` to the request config. `generateText` and `generateObject` send it to Converse without `streamProcessingMode`, which only ConverseStream has, and `streamText` sends it as given. An override replaces the whole object, and `guardrailConfig: undefined` turns a layer's guardrail off for one request.
- Put `metadata.amazonBedrock` on every finish part, on `generateText` and on `streamText`. `stopReason` is the Converse stop reason as Bedrock sent it, so `guardrail_intervened` and `content_filtered` can be told apart, though both still finish with `"content-filter"`. `guardrail` says whether a guardrail blocked or masked the input and the output, read from the trace, and `trace` is the trace as Bedrock sent it. Both are `null` unless the guardrail config enables the trace.
- Fail `generateObject` with an `AiError` whose reason is `ContentPolicyError` when a guardrail intervened and the response holds no JSON. In 0.3.0 the blocked message reached the JSON decoder, which failed with a retryable `StructuredOutputError`. A guardrail that the account or organization enforces can cause this without any `guardrailConfig` in the request.
- Add the `guardContent` option to user text parts, system messages, and user PNG and JPEG file parts. Once a part has it, the guardrail evaluates only the parts that have it. On text, `qualifiers` names the role of the text in a contextual grounding check. Any other part with the option fails with `InvalidUserInputError`.
- `AmazonBedrockClient.Service.converseStream` takes the new `ConverseStreamRequest`, and `Config` is derived from it. The new schemas `GuardrailConfiguration`, `GuardrailStreamConfiguration`, and `GuardrailConverseContentBlock` follow the Smithy shapes, and `ConverseResponse` and `ConverseStreamMetadataEvent` decode `trace`.
- Name the account data retention setting in the `InvalidRequestError` when Bedrock rejects a model with `data retention mode '<mode>' is not available for this model`. Claude Fable 5 and 5.1 need the mode `aws_review`, and the Converse API has no request field for it, so the AWS message alone did not say how to make the model callable. The README section "Choose a model" explains the setting.

## 0.3.0

`generateObject` asks models outside Anthropic for the object through a tool. In 0.2.0 it sent them `outputConfig.textFormat`, which Nova, Mistral Large 2402, Pixtral Large, Llama, and Palmyra answered with a 400 in probes in `eu-west-1` and `us-east-1`, so `generateObject` on these models failed unless you set `structuredOutputs: false`.

- Choose how `generateObject` asks for the object from the provider that the model ID names. Claude models keep the 0.2.0 behavior. Meta and Writer models get the object tool unforced, with a system prompt line that tells the model to call it, because Llama and Palmyra reject a forced `toolChoice`. Models of every other provider get the forced object tool. An ARN that does not name its model, such as an application inference profile, keeps the 0.2.0 behavior. `Config.structuredOutputs` and `Config.forcedToolChoice` still override the choice.
- Models of other providers that accepted `outputConfig.textFormat` in the probes, such as gpt-5.x, Grok, Qwen, GLM, MiniMax, DeepSeek V3.2, and Mistral Large 3, also get the object tool now. The object tool replaces the tools that you pass to `generateObject`, and in 0.2.0 these models kept them. Set `structuredOutputs: true` to keep the 0.2.0 behavior.
- Force the object tool with `toolChoice` `{ any: {} }` in place of `{ tool: { name } }`. The object tool is the only tool in its request, so both force it, and Mistral Large 2402 and Pixtral Large accept only `any`. A `toolChoice` that you pass with your own tools goes to Bedrock as before.
- Fail `streamText` with an `AiError` whose reason is `InvalidOutputError` when Bedrock streams tool input that is not valid JSON. In 0.2.0 the stream died with a defect. Bedrock streamed such input for Qwen3 32B in each probe run.
- Decode a stop reason outside the nine that the Converse API names, and give it the finish reason `"other"`. In 0.2.0 such a reason failed `generateText` and `streamText` with an `InvalidOutputError`, and the text before it was lost. The `StopReason` type now admits any string, so a `switch` over it that was exhaustive needs a `default` case, and a `Record` keyed by it no longer compiles. The new `KnownStopReason` schema holds the nine.

## 0.2.0

`AmazonBedrockClient.layer`, `layerConfig`, and `make` take one of three ways to authenticate: the fixed keys of 0.1.0, a `credentialProvider`, or a Bedrock `apiKey`. Options that mix two ways, or give none, do not compile. Every 0.1.0 call compiles and runs unchanged.

- Add the `credentialProvider` option. It takes a function in the shape of the AWS SDK's credential providers, such as `fromNodeProviderChain()` from `@aws-sdk/credential-providers`, or an `Effect`. The package does not depend on the AWS SDK. The client runs the provider when a request needs credentials, runs it once for concurrent requests, and keeps the credentials until five minutes before their `expiration`, or for at least 10 seconds.
- Keep the last credentials while the provider fails and they have not expired. Ask the provider again after 30 seconds, or when the last credentials expire if that is sooner.
- Refresh credentials that Bedrock rejects. After an `AuthenticationError` of kind `ExpiredKey`, `InvalidKey`, or `MissingKey`, the next request gets new credentials, and a function provider gets `{ forceRefresh: true }`. The rejected request fails and is not sent again.
- Fail a request with an `AuthenticationError` of kind `Unknown` when the promise of a function provider rejects, and of kind `MissingKey` when a provider returns an empty key.
- An `Effect` provider fails with an `AiError`, which the request fails with unchanged, or with an `AiError` reason, which the client puts in an `AiError`. The services that it requires become requirements of the layer through a new type parameter. It runs with the services of the request first, and the services that the layer was built with fill in the rest, so a span that it opens is a child of the request's span.
- Add the `apiKey` option for Bedrock API keys. The client sends the key as `Authorization: Bearer <key>` in place of a SigV4 signature, and an `AiError` shows the header as `<redacted>`.
- AWS rejects an API key that it does not accept with `AccessDeniedException`, as it rejects a missing IAM permission, so the request fails with an `AuthenticationError` of kind `InsufficientPermissions`.
- Add the `Credentials`, `CredentialProvider`, and `ConfigOptions` types. `Options`, `ConfigOptions`, `CredentialProvider`, `make`, `layer`, and `layerConfig` take a type parameter `R` for the services of an `Effect` provider. It defaults to `never`.
- A retry policy in `transformClient` or `AmazonBedrockConfig.withClientTransform` signs each attempt again with the credentials of the request, and does not retry a provider that fails.

## 0.1.0

The first release. It adds an Amazon Bedrock provider for `effect/ai`. The provider calls the Converse and ConverseStream APIs, signs requests with SigV4 through `aws4fetch`, and decodes the AWS event-stream framing without another dependency. `AmazonBedrockClient.layer` and `AmazonBedrockClient.layerConfig` take an access key and a secret key, and the optional `sessionToken`, `region`, `apiUrl`, and `transformClient`. The region defaults to `us-east-1`. `AmazonBedrockLanguageModel.Config` takes the Converse request fields other than `messages` and `system`.

- Add tool calling to `generateText`. The provider sends `toolConfig` with the tools and the `toolChoice`, decodes `toolUse` blocks into `tool-call` parts, and sends tool results back as `toolResult` blocks.
- Add tool calling to `streamText`. Streamed tool calls arrive as `tool-params-start`, `tool-params-delta`, `tool-params-end`, and a final `tool-call` part.
- Add structured output. `generateObject` sends the schema in the Converse `outputConfig.textFormat` field, so your own tools can go with it. The models on the provider's list, which are the Claude 3 models and Claude Sonnet 4 and Opus 4, get the object through a tool that replaces your tools. If the model calls the tool more than once, the first call is the object. Every model also gets the tool when `structuredOutputs` is `false`, and when the prompt holds tool calls but no tools go out, because Converse rejects such a request without a `toolConfig`. On the tool path, models that reject a forced `toolChoice`, such as Claude Opus 5.5 and Sonnet 5.5, get the tool unforced. `Config.structuredOutputs` overrides the choice of path, `Config.forcedToolChoice` overrides whether the tool is forced, and `Config.outputConfig` takes `effort`.
- Send `file` prompt parts as Converse `image` and `document` blocks. The provider accepts JPEG, PNG, GIF, and WebP images, and PDF, CSV, DOC, DOCX, XLS, XLSX, HTML, TXT, and Markdown documents. File data can be base64, a `Uint8Array`, or an `s3://` URL. Other media types and other URLs fail with `InvalidUserInputError`.
- Send a cited `text/*` document as a `text` source instead of base64. An uncited text document still goes as `bytes`, because Converse rejects a `text` source without a citations config.
- Send `context` on a document block through the `amazonBedrock.context` option of a file part.
- Add document citations. The `amazonBedrock.citations` option of a file part opts the document in. Citations come back as `source` parts whose `amazonBedrock` metadata names the cited span.
- Add prompt caching. The `amazonBedrock.cachePoint` option of a message or part adds a cache point after that content, with an optional `ttl` of `"5m"` or `"1h"`.
- Add tool-definition caching. Annotate a tool with `AmazonBedrockLanguageModel.ToolCachePoint` to cache the tool list up to that tool.
- Add reasoning. `reasoningContent` blocks decode into `reasoning` parts on both paths, and reasoning parts go back to Bedrock in later turns with their signature or redacted payload.
- Pass model-specific fields through `Config.additionalModelRequestFields`, such as the `thinking` block that turns on extended thinking.
- Fail a 401 or 403 response with an `AuthenticationError` that keeps the AWS error message. The message tells wrong credentials apart from a model that the account cannot use. The `kind` of the error comes from the AWS exception name in the `x-amzn-errortype` header. `AccessDeniedException` gives `InsufficientPermissions`, and `ExpiredTokenException` gives `ExpiredKey`. `UnrecognizedClientException`, `InvalidSignatureException`, and `IncompleteSignatureException` give `InvalidKey`, and `MissingAuthenticationTokenException` gives `MissingKey`. Without the header, or with another name, a 401 gives `InvalidKey` and a 403 gives `InsufficientPermissions`.
- Fail `generateText` and `streamText` with `InvalidUserInputError`, before the request is sent, when the prompt holds tool calls or tool results and the request carries no `toolConfig`. Converse answers such a request with a 400. The error names the workaround: pass the toolkit that produced the tool calls, with `toolChoice: "auto"`.
- Redact the `X-Amz-Security-Token` header in the request and response headers of an `AiError` and in an HTTP span that records headers. `converse` and `converseStream` add the header to the names in `Headers.CurrentRedactedNames`, so the names that you set stay redacted too. An error from a request signed with temporary credentials does not show the session token.
